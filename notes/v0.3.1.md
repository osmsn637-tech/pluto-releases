# Pluto CLI v0.3.1

This release makes engine repair download about 750 KB instead of the whole
1.3 GB engine when only the files Flutter and git rewrite have drifted. The SDK
is unchanged from v0.3.0.

## Smaller engine repairs

- An installed engine keeps verified copies of the few files Flutter and git
  rewrite on every run. Installs made before a file joined that list, or whose
  copies were lost, failed verification, and `pluto engine install --repair`
  downloaded the whole engine again.
- The Flutter 3.47.1 engine release now has a small runtime snapshot asset,
  pinned by size and SHA-256 in the CLI's catalog. Repair downloads it first,
  swaps it in, and keeps it only when the whole engine then matches the
  published fingerprint; it prints "Restored the files Flutter and git
  rewrite; the engine was not downloaded again". Any other drift, or a
  snapshot that does not fix it, falls back to the full reinstall as before.
- `pluto-engine-bundle runtime-snapshot` builds the asset from an installed,
  verified engine for future engine releases.

## Existing applications

Run `pluto self-update`. An engine that fails `pluto engine status` after the
update to v0.3.0 needs only `pluto engine install --repair --yes`, which now
fetches the small snapshot. No new baseline is needed.

## Validation and limits

The Go suite, deterministic SDK export and release packaging passed. Tests
cover a repair restored from the snapshot alone, a repair that falls back to
the full download when another engine file changed, and a tampered snapshot
asset. On this Mac, an installed engine whose snapshot was removed after
Flutter had rewritten its files was repaired from the published asset without
downloading the engine, and then verified.

CLI archives target `darwin-arm64`, `darwin-amd64`, and `linux-amd64`. Each
contains only `pluto` and `THIRD_PARTY_NOTICES.txt` and ships with its checksum
and signature using the existing release trust root.
