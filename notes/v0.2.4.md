# Pluto CLI v0.2.4

This release adds the build inputs, workspace resolution, deployment binding,
and running-release identity needed by QEU, together with automatic activation
for new integrations.

- `baseline build` and Android `patch build` accept `--obfuscate`,
  `--split-debug-info`, and repeated `--dart-define-from-file`. Each build keeps
  separate symbols and an obfuscation map and reports their paths.
- Pub workspace apps use the shared package config and lockfile. Workspace Dart
  remains patchable; native files, assets, resolution changes, and the pinned
  SDK checkout remain part of the baseline contract.
- `--config FILE` chooses a complete named environment and supplied registry.
  Baselines bind the server identity and compiler settings; patch verification
  rejects a different environment. Android receives a build-scoped resource
  overlay without rewriting checked-in configuration.
- `Pluto.currentRelease()` reports the loaded release, artifact SHA-256,
  baseline ID, and iOS runtime family ID at startup. Bundled code is release 0
  with a null artifact hash; a staged update does not change this identity.
- Android configuration resources survive release resource shrinking. Both
  SDKs discard expired or permanently rejected telemetry and retain retries for
  transient failures. Canonical server candidate and endpoint contracts stay
  unchanged.
- New onboarding defaults to `guarded_in_process` on iOS and
  `managed_process_restart` on Android. `--activate auto` selects these modes;
  existing target modes remain unchanged when that flag is omitted.
- Android managed restart supports `singleTask` without changing the app's
  call or deep-link routing. A private temporary task keeps the restart
  coordinator alive while the original host task is preserved. CLI preflight
  checks launch modes across selected release/flavor/variant manifests.
- A successor process can replace an orphaned restart record with a newer
  verified pending update after APK replacement. Pending/active references,
  activation attempts, and malformed state still block replacement.
- Android sends a fresh `healthy` status after successful patch activation or
  baseline restoration, in addition to the activation event.
- Android honors `checkForUpdate(activateWhenSafe: true)`. Both platforms allow
  staging only with `false` and report missing activation guards clearly.
- Integration supports a main function that delegates to an app bootstrap,
  without injecting foreground startup into background handlers. Android
  fingerprints exclude generated native build caches such as `.cxx`.
- Pins SDK commit `043072311ccdfe40486c0f4b15ddee90c8c6f8e2` from
  `qeuapp/pluto-sdk`.

## Existing applications

After updating the CLI, update each supplied app registry's SDK pin before
re-running onboarding. Keep the registered app IDs and public keys; do not
create replacement signing keys:

```sh
pluto self-update
pluto app pin APP_ID --package-ref 043072311ccdfe40486c0f4b15ddee90c8c6f8e2
pluto onboard --app APP_ID --platform android --activate auto
```

Use `--platform ios` with the separate iOS app ID. Review activation guards,
checkpoints, health checks, and the iOS native plugin lifecycle audit, then
build a new baseline. Existing baselines without deployment binding require a
new baseline before patching with this CLI. Automatic activation mode changes
also require a new baseline.

iOS replaces the Flutter engine in the existing process. Android restarts into
a new process automatically. iOS module obfuscation and App Store remote-code
delivery are not completed capabilities; host AOT obfuscation does not obscure
bytecode modules. Flutter 3.47.1 remains the pinned engine.

## Validation and limits

The complete Go suite, CLI dependency boundaries, Dart tests and analysis,
Android native unit tests, deterministic SDK export, and CLI packaging checks
passed. Regression coverage includes workspace Dart versus native changes,
shared-lock rollback, define-file precedence, environment mismatch rejection,
startup release identity, status delivery, and native build-cache exclusion.

The QEU mobile app built an obfuscated, minified Android baseline and patch
using two JSON define files, with separate symbol/obfuscation-map outputs.
Patch verification passed, and APK inspection confirmed native configuration
resources survived shrinking. The temporary Dart change was restored.

The final SDK passed the actual QEU roundtrip on POCO Android 16: automatic
`singleTask` restart, patch B loaded in a new PID, exact `currentRelease()` identity,
and a fresh server `healthy` event with no pending release or failure. App and
installation identity were preserved. The same installation also accepted a newer
signed release after an earlier health timeout and automatic baseline recovery.
All 121 Android native tests passed. Device patches used an isolated local server
and an explicitly enabled test panel; production health/activation guards still
need application integration. Sentry crash symbolication and physical QEU iOS
checks remain open; this release provides no unmeasured iOS performance numbers.

CLI archives target `darwin-arm64`, `darwin-amd64`, and `linux-amd64`. Each
contains only `pluto` and `THIRD_PARTY_NOTICES.txt` and ships with its checksum
and signature using the existing release trust root.
