# Pluto CLI v0.2.4

New CLI integrations now select automatic activation for each platform, and
the Android SDK honors `checkForUpdate(activateWhenSafe: true)` instead of
ignoring the activation request.

- New `onboard`, `init`, and `app config` targets select
  `guarded_in_process` on iOS and `managed_process_restart` on Android.
- `--activate auto` selects both modes in combined onboarding. Existing target
  modes remain unchanged when the flag is omitted; `next_cold_launch` remains
  an explicit option.
- Both SDKs support `checkForUpdate(activateWhenSafe: false)` for apps whose
  existing controller owns activation.
- Missing guards report `blocked` / `activation_guard_missing`. iOS reports
  specific reasons for cold-launch configuration, unsafe plugin lifecycle,
  and the bundled-rollback limitation.
- CLI setup output explains activation prerequisites. Initialization/config
  JSON includes the selected `activation_mode`.
- Pins SDK commit `dae88b030ce762085b7483e9a96f1a16233a274f` from
  `qeuapp/pluto-sdk`.

## Existing applications

After updating the CLI, explicitly update each app registry's SDK pin before
re-running onboarding:

```sh
pluto self-update
pluto app pin APP_ID --package-ref dae88b030ce762085b7483e9a96f1a16233a274f
pluto onboard --app APP_ID --platform b --activate auto
```

Review the integration, keep the app's guards/checkpoints/health checks, and
complete the iOS native plugin audit before using `pluto install` to build and
install a new baseline. Mode changes affect native baseline identity; an OTA
patch cannot enable automatic activation in an existing cold-launch baseline.
Use `--platform a` or `--platform i` for an app with only one platform.

iOS activation replaces the Flutter engine inside the existing process.
Android activation creates a new process automatically. Android's existing
host/custom-Application restrictions and iOS's plugin lifecycle checks still
apply. iOS remains an internal beta; this release makes no new distribution
or physical-device validation claim.

## Validation and artifacts

The complete Go test suite, CLI dependency boundaries, 54 Flutter tests,
analysis of all three changed Dart packages, deterministic SDK export checks,
and CLI release-packaging tests passed. No new physical-device run was made.

CLI archives are provided for `darwin-arm64`, `darwin-amd64`, and
`linux-amd64`. Each contains only `pluto` and `THIRD_PARTY_NOTICES.txt` and
ships with its checksum and signature using the existing release trust root.
